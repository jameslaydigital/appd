Commands

CommandDoes
appd installCopy this binary to /usr/local/bin, write the man page and completions, and create /etc/appd. --prefix, --destdir, --uninstall.
appd install-app DIRFind DIR/.appd.conf, validate it, and install it as /etc/appd/<project>.json. --name, --apply.
appd skills install [DIR]Write .agents/skills/appd/SKILL.md into a project; --claude, --codex, --opencode select their layouts.
appd initCreate /etc/appd without installing the binary. Idempotent; no root needed if it already exists.
appd apply [APP…|all]Render configs, write units, daemon-reload. --prune removes orphaned units; --yes skips the all-confirmation.
appd diff [APP…|all]Show how installed units differ from their configs. Exits 1 on drift.
appd doctorRead-only preflight. Exits 1 when it finds a problem.
appd status [APP…|all]One table row per app, or a detail view for one app.
appd start|stop|restart|reloadsystemd verbs. reload uses the config’s reload command and refuses without one.
appd enable|disableBoot behaviour. Separate from apply and start.
appd logs APPJournal output. -f, -n N, --since, -p LEVEL.
appd error-logs APPlogs with -p err. Empty if the app emits only priority 6.
appd remove APPDelete the unit, config, provisioned account, and state directory. --keep-user, --keep-state, --yes.
appd manPrint the man page (roff) to stdout.
appd completions SHELLPrint a completion script for bash, zsh, fish, elvish, or PowerShell.
appdInteractive TUI. Not available through a pipe; that prints status all.

Configuration

One file per app at /etc/appd/<app>.json. JSON is strict: unknown keys are errors, and one bad file aborts the whole apply before anything is written.

json 
{
  "description": "Sundial notes API",
  "exec": "/srv/sundial/bin/sundial-api",
  "args": ["--bind", "127.0.0.1:8787"],
  "working_directory": "/srv/sundial",
  "restart": "on-failure",
  "environment_file": "/etc/appd/sundial.env",
  "permissions": {
    "network": true,
    "write": ["/srv/sundial/public"]
  }
}
FieldDefaultNotes
descriptionapp nameDescription= in the unit.
execrequiredAbsolute path to the binary.
args[]Arguments passed to exec; quoted when they contain spaces.
working_directorystate directoryAbsolute path.
userappd-<app>Omit to provision the account. "root" is allowed but must be written explicitly.
groupsame as userExisting group name.
restarton-failureno, always, on-success, on-abnormal, on-abort, on-watchdog.
restart_secsystemd (100 ms)Seconds between restarts.
umasksystemd1–4 octal digits, e.g. "0027".
reloadnoneArgv array for appd reload; without it, reload refuses and points at restart.
wanted_by["multi-user.target"]What enable links into.
environment{}Inline variables. Secrets belong in an environment file.
environment_filenonePath or array. Read by systemd as root; 0600 is fine.
permissions.networkfalseOpens AF_INET/AF_INET6. Unix sockets are always available.
permissions.read[]ReadOnlyPaths=. Rarely needed under ProtectSystem=strict.
permissions.write[]ReadWritePaths=. The path must exist or the unit fails with 226/NAMESPACE.
permissions.executable_memoryfalseDisables MemoryDenyWriteExecute for JIT runtimes. Node/V8 dies with SIGTRAP without it.
permissions.devices[]DeviceAllow= entries.
permissions.apparmornoneAttaches an existing profile by name; appd does not generate one.

Logging

appdjournalctl
appd logs appjournalctl -u appd-app.service
appd logs app -f… -f
appd logs app -n 200… -n 200
appd logs app --since 1h… --since 1h
appd error-logs app… -p err

journald records both stdout and stderr at priority 6. To make a line show up in error-logs, the app tags it with a syslog priority: <3> for err, <4> for warning. journald strips the prefix and stores the priority. Anything using syslog(3) or sd_journal_print(LOG_ERR, …) does this automatically.

Rules

Names

App names come from the config filename: lowercase letters, digits, and dashes, up to 27 characters. all is reserved. The derived account has to fit Linux’s 32-character username limit, which is where 27 comes from (appd- is five).

Root and non-root

init, install, apply, remove, and the service verbs need root. status, logs, error-logs, and the TUI work as any user. Configs are 0600, so a non-root status takes app names from the directory and state from systemd; the notes column says config unreadable, run as root.

Apply semantics

apply writes units and reloads systemd. It does not start, stop, enable, or restart. Those are separate commands, and the output names what still needs one.

Collisions

Every unit is prefixed appd- and carries the marker. appd refuses to overwrite a unit it did not write. Renaming a config leaves the old unit as an orphan; apply --prune removes it. The account and state directory are left for appd remove.

Exit codes

CodeMeaning
0Success; for diff, no drift; for doctor, no problems.
1Failure, drift, or problems. Safe to use as a CI gate.

Doctor checks

  • exec exists and is executable by the service account, including every parent directory.
  • Config mode and environment files; warns when secrets are group- or world-readable.
  • Permission paths and working directory exist.
  • The configured reload command exists.
  • The unit is installed, matches the config, and is enabled.
  • The provisioned account or the explicitly named user/group exists.
  • Orphaned units; a second appd on root’s PATH at a different version.
  • journald is available.

It reports and exits; it never fixes or writes. The fix lines name the command that does.

TUI keys

KeyAction
j / k, arrowsMove between apps.
enter / lToggle the log pane, following the selected app.
aApply configs: sync units and reload systemd. Does not restart.
r / sRestart or stop, with confirmation.
t / e / xStart, enable, or disable.
/ ? qFilter, help, quit.

Read-only sessions are marked in the header. Mutating keys print the sudo command instead of failing.
