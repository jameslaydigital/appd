Install

shell 
cargo install --locked appd
sudo "$(command -v appd)" install
sudo appd init

The second command copies the binary to /usr/local/bin, writes the man page, and installs completions. The third creates /etc/appd with mode 0755; config files stay 0600 because they may hold secrets.

The app

Sundial is a small notes API. It reads code and templates from /srv/sundial, writes rendered pages to /srv/sundial/public, and keeps credentials in an environment file.

layout 
/srv/sundial/
├── bin/sundial-api
├── templates/
└── public/          # rendered pages; the API writes here

Create the write directory and give it to the service account after the first apply creates that account. The unit opens the path; the filesystem still owns the permissions.

The config

Save this as /etc/appd/sundial.json. The filename becomes the app name, the unit name, and the account name.

json 
{
  "description": "Sundial notes API",
  "exec": "/srv/sundial/bin/sundial-api",
  "args": ["--bind", "127.0.0.1:8787"],
  "working_directory": "/srv/sundial",
  "restart": "on-failure",
  "reload": ["/bin/kill", "-HUP", "$MAINPID"],
  "environment_file": "/etc/appd/sundial.env",
  "permissions": {
    "network": true,
    "write": ["/srv/sundial/public"]
  }
}

There is no user field, so apply provisions appd-sundial. There is no state path, because systemd creates /var/lib/appd-sundial and makes it writable under ProtectSystem=strict.

The environment file is read by systemd as root, so it can stay 0600:

/etc/appd/sundial.env 
DATABASE_URL=postgres://sundial@127.0.0.1/sundial
SESSION_SECRET=replace-with-something-long

Doctor

Doctor is read-only. Run it before apply; it names what would fail at start time.

shell 
sudo appd doctor
output 
sundial
  ✗ environment file /etc/appd/sundial.env does not exist; the unit will fail to start
  ✗ service account `appd-sundial` does not exist
      fix: appd apply sundial
  ⚠ appd-sundial.service is not installed
      fix: appd apply sundial

1 app checked, 2 problems, 1 warning, 0 orphans

Create the environment file, then run doctor again. The account warning disappears after apply; the unit warning disappears after the unit is installed.

Apply, enable, start

shell 
sudo appd apply sundial
sudo appd enable sundial
sudo appd start sundial

apply writes /etc/systemd/system/appd-sundial.service, provisions the account, and reloads systemd. It does not start or enable anything. Those are the next two commands, separately.

After granting the write path to the new account, check the result:

shell 
sudo chown appd-sundial:appd-sundial /srv/sundial/public
appd status all
output 
APP      UNIT                  STATE    SINCE             PID    NOTES
sundial  appd-sundial.service  running  2026-10-26 14:02  41231

Logs

shell 
appd logs sundial -n 50
appd logs sundial -f
appd error-logs sundial

The backend is journald. error-logs filters to priority err; journald records plain stdout and stderr at priority 6, so an app has to tag a line with <3> to appear there. appd logs always shows the merged stream.

node 
// priority 3: visible in `appd error-logs`
process.stderr.write("<3>database connection lost\n");

Change a config

Add a flag to the API, then ask what that would do. diff exits 1 when the installed unit and the config disagree.

shell 
sudo appd diff sundial
sudo appd apply sundial
sudo appd restart sundial

If the change is something the process reads at runtime — a template, not an argument — use sudo appd reload sundial. It runs the configured reload command. Without one, appd refuses and tells you to restart instead of guessing at a signal.

Remove

shell 
sudo appd remove sundial

It prints exactly what will go: unit, config, provisioned account, state directory. --keep-user and --keep-state leave either behind. It never deletes the application binary, because appd did not install it.

When it breaks

SymptomCauseFix
status=203/EXEC The account cannot execute the binary, or a parent directory blocks it. appd doctor names the path; chmod o+rx it, or set an existing user.
status=226/NAMESPACE A path in permissions.read or permissions.write does not exist. Create the directory, or remove it from the config.
EROFS or permission denied on write The path is not opened in permissions.write, or the service account does not own it. Add the path, and chown it to the account.
error-logs is empty journald stores plain stderr at priority 6. Tag error lines with <3>, or use appd logs.
Behavior did not change after apply The running process still holds the old unit. appd restart sundial, or reload if the change is reloadable.
doctor warns about two versions The cargo copy and /usr/local/bin copy disagree. sudo "$(command -v appd)" install.

For everything else, the reference has the full config field list, and the repository’s TUTORIAL.md covers renaming, orphans, and hand-edited units.
